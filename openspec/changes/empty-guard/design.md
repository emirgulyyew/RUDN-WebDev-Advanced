## Контекст

Компонент `NewCardForm` — простая форма с одним полем ввода (`<input>`) и кнопкой отправки (`<button type="button">`). В текущей реализации:

- Поле ввода не связано со состоянием (нет `value` / `onChange`).
- Кнопка имеет `type="button"`, но не проверяет содержимое поля.
- Нет валидации, нет визуальной обратной связи.

## Решения

### 1. Controlled input

Использовать React `useState` для управления значением инпута:

```tsx
const [title, setTitle] = useState("");
const [touched, setTouched] = useState(false);
```

- `title` — текущее значение поля.
- `touched` — флаг, показывающий, пытался ли пользователь отправить форму (определяет, показывать ли ошибку).

### 2. Обрезка пробелов

При проверке на пустоту использовать `title.trim()`:

```tsx
const isEmpty = title.trim() === "";
```

Кнопка получает `disabled={isEmpty}`.

### 3. Визуальная обратная связь

- CSS-класс `.input--error` добавляется к инпуту, когда `touched && isEmpty`.
- Класс управляет красной рамкой (`border-color: red`).
- Рядом с инпутом рендерится `<span className={styles.error}>Введите название карточки</span>`, видимый только когда `touched && isEmpty`.
- При изменении инпута (`onChange`) флаг `touched` сбрасывается, скрывая ошибку.

### 4. Отправка

Кнопка имеет `type="button"` и `onClick`, который:

1. Устанавливает `touched = true`.
2. Если `!isEmpty` — вызывает существующий колбэк добавления карточки (будет добавлен позже).
3. Если `isEmpty` — ничего не делает, показывает ошибку.

## Альтернативы

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| `<button type="submit">` + `<form onSubmit>` | Нативная обработка Enter | Требует обёртки `<form>`, может конфликтовать с будущей логикой |
| `disabled` только, без визуальной обратной связи | Проще | Пользователь не понимает, почему кнопка не работает |
| HTML5 `required` + `pattern` | Без JS | Не обрезает пробелы, недостаточно для UX |

**Выбрано**: controlled input + `disabled` + визуальная обратная связь — баланс простоты и UX.
