# Design: Удаление карточки (KAN-3)

## 1. Цель

Добавить серверную поддержку удаления карточки и корректную обработку ошибок на уровне маршрутизации Express.

## 2. Технический контекст

- **Фреймворк:** Express.js (Node.js + TypeScript)
- **Файл:** `server/index.ts`
- **Хранилище:** массив `cards` в памяти (без базы данных)
- **Типизация:** TypeScript, тип `Card` уже определён

## 3. Архитектурные решения

### 3.1 Порядок регистрации обработчиков

Express обрабатывает маршруты последовательно, поэтому порядок критичен:

1. `express.json()` — парсинг тела запроса (уже есть)
2. `GET /cards` — список карточек (уже есть)
3. `POST /cards` — создание карточки (уже есть)
4. **`DELETE /cards/:id`** — удаление карточки (новый)
5. **`app.use` — обработчик 404** для неизвестных путей (новый)
6. **`app.use` — глобальный обработчик ошибок** с 4 параметрами (новый)

Обработчики 404 и ошибок реализованы как мидлвар через `app.use()`, размещённые после всех маршрутов.

### 3.2 Удаление из массива

Используется `Array.findIndex()` для поиска по `id`, затем `Array.splice()` для удаления. Это O(n) операция, что приемлемо для текущего объёма данных.

### 3.3 Формат ответов

Все ответы — JSON с `Content-Type: application/json`, устанавливаемым автоматически через `res.json()`. Это обеспечивает единообразие и корректную сериализацию.

### 3.4 Обработка ошибок

Глобальный обработчик ошибок — Express-мидлвар с сигнатурой `(err, req, res, next)`. Express автоматически распознаёт такие функции как обработчики ошибок и передаёт их только при вызове `next(err)` или при unhandled exception.

## 4. Распределение по файлам

| Файл | Изменение | Обоснование |
| ---- | --------- | ----------- |
| `server/index.ts` | Добавить 3 блока кода | Единственный файл серверной части; клиент не затрагивается |

## 5. Риски

- **Порядок мидлваров:** если обработчик 404 или ошибок разместить до маршрутов, маршруты не будут достижимы.
- **Отсутствие валидации типа id:** `req.params.id` всегда строка; так как `Card.id` — строка, совпадение работает корректно.
